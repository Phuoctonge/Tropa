# Tropa

На 28 октября добавлено [раздельное туннелирование приложений](validation/split-tunneling.md): весь компьютер либо только выбранные EXE через WARP. Остальные приложения в выборочном режиме идут напрямую. Прежний выбор игры сам по себе маршрутизацию не менял; он сохранён только как предложение добавить ранее выбранный EXE. Нативный тест подтвердил разделение двух процессов для IPv4 HTTPS/TCP; браузеры, UDP и IPv6 отдельно пока не проверены.

Portable здесь означает готовую папку из ZIP: приложение, DLL, ядро и остальные необходимые файлы. Один exe не обязателен. Пользователь распаковывает архив и запускает Tropa без установщика. По последнему запросу пользователя portable-EXE требует права администратора сразу при запуске через манифест Windows.

Бесплатный открытый WARP-клиент для Windows с отдельной будущей оптимизацией для игр. Обычное подключение не требует выбора игры: автоматический подбор и ручной выбор сервера работают независимо от неё. [Актуальный сценарий выбора серверов](superpowers/specs/2026-10-27-server-selection-design.md) заменяет ранний сценарий «сначала выбрать игру». Снижение задержки проверяется измерениями.

Кнопка «Сервер» открывает таблицу справа в том же окне; закрытие панели возвращает прежний размер. Быстрое подключение проверяет сохранённый профиль или ищет один рабочий вариант. Отдельный расширенный поиск использует полный отчёт WarpScout с `-P` и проверяет адреса ядром Tropa, сохраняя результаты постепенно. Лимит — 128 профилей и десять минут поиска плюс завершение текущей проверки. Протокол, пинг адреса, пинг туннеля, потери, узел и страна выходного IP показаны отдельно; UDP DNS и время измерений доступны в подробностях.

На 27 октября 2026 года разработка начата: исходники Clash Verge Rev v2.5.8 получены с историей, frontend-зависимости установлены, TypeScript, ESLint и 45 тестов прошли, веб-интерфейс собран. Статус нативной сборки и portable-проверок находится в [отчёте сборки](validation/build.md). Текущая папка — проект Tropa.

Требования пользователя: основа — форк Clash Verge Rev; поставка — portable, без установщика и постоянно установленной службы. Права администратора запрашиваются при запуске. Реальные автоматическое подключение TUN и отключение проверены на текущей Windows; проверка чистой Windows ещё предстоит.

## Текущее решение

Основа: узкий форк Clash Verge Rev; единственное сетевое ядро — upstream mihomo; сканирование — WarpScout. Собственный код отвечает за игровые профили, выбор процессов, сравнение вариантов подключения и простой интерфейс. Ядро запускается на время подключения; постоянно установленная служба не входит в portable-версию.

Выбор оболочки условный до проверки portable-запуска, маршрутизации и ресурсов. Если Clash Verge Rev требует постоянной службы, сначала оцениваем ограниченную адаптацию запуска; собственная оболочка рассматривается только при доказанной необходимости. Переписывание сетевых протоколов в первую версию не входит.

## Что пока не сделано

Рабочая ветка — codex/foundation-validation. Проверены реальное TUN-подключение и отключение, повторное подключение и запуск минимального portable-комплекта; постоянно установленная служба не используется. Результаты и ограничения описаны в [отчёте подключения](validation/production-connection.md). Ещё не проверены игры, античиты, запуск на чистой Windows и нативное взаимодействие с новой расширяемой панелью. Регистрация, общий runtime и поиск MASQUE H3/H2 добавлены в исходники с локальными тестами; реальное подключение этих режимов пока не проверялось. Оптимизация для конкретной игры остаётся отдельной работой. Актуальное исполнение — в [дорожной карте](roadmap.md).

## Получение исходников

Исходники Tropa находятся в корне проекта с сохранением истории upstream, этой документации и оригинальных LICENSE/README. Безопасный импорт зафиксирован в [плане первой сборки](superpowers/plans/2026-10-27-tropa-first-build.md). Новые обновления upstream принимаются с просмотром коллизий и diff.

Для локальной сборки публичный GitHub-форк не обязателен. Публикация исходников и релизов — отдельный шаг. Ключи WARP хранятся вне Git; данные portable-приложения размещаются рядом с его исполняемым файлом, вне checkout разработчика. Сетевые испытания начинаются после успешной сборки.
