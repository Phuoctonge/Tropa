# Tropa: текущее состояние и план завершения

Дополнительный IPv6-прогон ordinary `l` выявил отказ до TUN: все IPv6-запросы упираются в DNS, а с явным AAAA — в немедленный отказ подключения; IPv4 selected/direct продолжает работать. IPv6 binding Tropa включён, но адреса и unicast-маршрута нет. В закреплённом mihomo найдена проверка IPv6-интерфейсов до создания TUN, которая на таком хосте убирает IPv6 из TUN. [Наблюдения и следующий контролируемый тест](validation/production-connection.md#ordinary-package-l--ipv6-blocked-before-tun-capture-on-this-host). Рабочий IPv6 или исправление этим не объявлены.

Повторные подключения H2 проверены отдельным diagnostic EXE через production connection/disconnect: один пробный и 20 последовательных циклов. Во всех 21 выбранный IPv4 HTTPS EXE прошёл off → on → off, контрольный остался напрямую; сеть, регистрация, временные файлы и процессы проверены после каждого цикла. [Доказательства и границы](validation/production-connection.md#repeated-clean-core-h2-lifecycle--21-diagnostic-cycles). Это не 20 ручных GUI-прогонов ordinary ZIP. 60 минут, сон, смена сети, аварии, другие транспорты и полный UDP/IPv6 остаются открытыми.

Браузерная проверка ordinary `l` также выполнена: Firefox добавлен через GUI picker, Chrome не выбран. По присланным пользователем trace-страницам Firefox прошёл off → on (HTTP/3) → off, Chrome остался off на HTTP/2; независимый system curl тоже оставался напрямую. Сеть после отключения восстановилась. [Метод и ограничения](validation/production-connection.md#ordinary-package-l--firefox-selected--chrome-direct). Это один подтверждённый QUIC-запрос внутри H2-туннеля; DoH, MASQUE H3, произвольный UDP, IPv6 и длительные сокеты этим не закрыты.

Последующая native-приёмка ZIP `l`: пользователь запустил обычный EXE, подтвердились полный H2 TUN, сохранение соединения при крестике в трей и очистка при «Выход». Отдельно подтвердилось выборочное IPv4 HTTP/HTTPS TCP по точному пути: из трёх побайтно одинаковых `curl.exe` через WARP шёл только выбранный. После отключения сеть вернулась к baseline, registrations и ручной профиль сохранились, runtime config удалён. [Scope и evidence](validation/production-connection.md). Это не проверка браузеров/UDP/IPv6, старых сокетов, 20 циклов/60 минут или чистой Windows. Прежние заявления ниже об отсутствии любого актуального TUN/tray evidence относятся к состоянию до этих прогонов.

## 1. Какой результат строим

Windows x64 portable-приложение: распаковать папку, запустить Tropa.exe, подтвердить UAC и подключиться. DLL, дополнительные EXE и папки допустимы. Установщик и постоянно установленная служба не нужны.

На главном экране — подключение, выбранный сервер и краткий статус. Панель серверов расширяет основное окно. Поиск и подключение работают независимо от выбора игры. Пользователь может доверить выбор автоматике или закрепить точный профиль. Крестик скрывает окно в трей; явный выход отключает соединение и завершает принадлежащие Tropa процессы.

Обычное подключение, разделение приложений и игровые измерения — разные функции. Выбор EXE задаёт маршрутизацию; он не меняет права процесса и не означает инжект.

## 2. Архитектура, которую сохраняем

| Часть | Ответственность | Как обновляется |
| --- | --- | --- |
| React / TypeScript | Интерфейс, таблица, настройки, отображение статуса | Вместе с Tropa после frontend-проверок |
| Rust / Tauri | Регистрация, ограничения, планирование, кэш, управление процессами, подключение | Собственная сборка Tropa |
| Собственный Go-компонент `tropa-probe.exe` | Сеансы WG/AWG/MASQUE, handshake, передача данных и измерения при поиске | Обновление закреплённых библиотек, пересборка, проверка wire-контракта и исходников |
| `verge-mihomo.exe` | Рабочий туннель и маршрутизация приложений | Проверенный отдельный EXE с закреплённой версией и хэшем; это имя файла mihomo, а не отдельная оболочка над ним |
| Wintun / WebView2 | Системный туннель / отображение интерфейса | По применимым условиям поставки и отдельной проверке совместимости |

Между Rust и Go — двусторонний протокол по унаследованным pipes. Здесь нет запуска WarpScout, чтения его таблицы или локального HTTP-сервиса. Ключи передаются только через pipe; worker не является владельцем регистрации и не сохраняет её.

Поиск использует userspace-туннели без изменения системных маршрутов. После поиска worker должен завершиться и освободить владение, затем кандидаты проверяются через поставляемый mihomo. Пересечение поиска с активным пользовательским туннелем пока запрещено.

## 4. Что важно не считать законченным

1. Source cutover и удаление WarpScout EXE из упаковки выполнены; ordinary ZIP `g` прошёл прежний статический verifier, но не свой native TUN smoke. Генератор инвентаризации теперь включает worker SHA/build/source/protocol и notices; текущий verifier сверяет запись с доверенным engine build. Генератор README уточнён под переподключение, папки и настройку крестика; архив `g` ещё содержит прежний текст и inventory.
2. `advanced` уже передаётся планировщику и ограничивает широкий подбор. Нужны измерения полного расширенного режима; quick-run не доказывает его длительность или покрытие.
3. Сохранённые точные параметры включены в worker-очередь с ограничением начальной порции; регрессия большого медленного кэша проходит. Нужна дальнейшая проверка на реальных сменах сети и отказах сохранённых профилей.
4. Ранний выход учитывает policy и HTTPS-кандидата; обычные native-прогоны измерены. Возобновление expansion после раннего runtime-отказа реализовано с исходной очередью и бюджетами. Тесты подтверждают сроки, неповторение initial pass и native cleanup; полный сценарий runtime-отказ → успех после продолжения ещё нужно воспроизвести. ZIP `g` предшествует этому исправлению. Полный табличный перебор измеряется отдельно.
5. Новая runtime-проверка сохраняет явный UDP DNS method; старые записи без него остаются неизвестными. Таблица и сортировка разделяют ICMP поиска и UDP DNS mihomo, учитывают возраст/контекст и не ранжируют неподдерживаемые методы по числам. Это ещё нужно посмотреть в обычном GUI; игровым ping эти значения не являются.
6. Страна узла и страна выходного IP различаются. Ограничение страны узла не гарантирует страну выхода. DTO и таблица показывают точные search metadata и этапы, сохраняя `untested` до runtime-проверки.
7. Нет доказательства всей цепочки нового Rust-поиска → потоковый каталог → остановка worker → проверка mihomo → подключение TUN на актуальной обычной сборке.
8. У закреплённого mihomo в inventory записаны `GOAMD64=v2` и `vcsModified=true`. Требование к CPU должно учитывать самый требовательный компонент; происхождение изменённой сборки требует подтверждения или собственной сборки из точно известных исходников.
9. WebView2 пока требуется отдельно. Полностью автономный запуск на чистой Windows без установки зависимостей не доказан.
10. Нет проверок реальных игр/античитов, гарантии отсутствия блокировок и реализованного отдельного измерения игровых направлений.

## 5. Порядок оставшейся работы

### A. Завершить поведение собственного поиска

**Файлы:** `src-tauri/src/core/warp_engine/{scheduler,runner,selection,stream}.rs`, `warp_discovery.rs`, `config/warp_profiles.rs`, `cmd/tropa.rs`, `src/types/tropa.ts`, `src/utils/tropa-server.ts`.

- Включить разрешённые сохранённые профили в начальные проверки с их точными SNI/I1/junk; не терять стандартные endpoints и не смешивать семейства адресов.
- Развести обычный поиск и явный подбор параметров. Нормальный проход сначала использует сохранённые и базовые варианты; широкие junk/SNI-переборы принадлежат подбору параметров. Не убирать необходимые базовые AWG I1-профили.
- Проверить раннюю передачу к runtime validation после достаточного начального покрытия; не завершать поиск до обслуживания всех разрешённых протоколов и не прерывать активную пользовательскую сессию.
- Явно маркировать источник/метод/цель измерений. Для сортировки сравнивать только сопоставимые измерения, учитывая потери, разброс, выборку, возраст и контекст сети.
- Показывать страну узла и выхода отдельно; неизвестные поля оставлять неизвестными.

**Готовность:** регрессии подтверждают точные параметры, кэш не даёт обхода свежей проверки, режимы различаются реально, ограничения действуют на адреса/кэш/проверку/подключение. Ни один протокол не забирает весь бюджет.

### B. Убрать WarpScout из исполняемой поставки

**Файлы:** `warp_scout.rs`, legacy-части `warp_search.rs`, account export helpers, `scripts/{prepare-tropa.mjs,build-tropa.py,package-tropa.py,tropa_bundle.py,tropa-components.json}`, `warp_diagnostics.rs`, notices и source snapshot inputs.

- Удалить ненужные CLI-команды, parser таблиц, временные scanner accounts/reports/configs и копирование warpscout.exe.
- Сделать source-bound worker обязательным для обычной portable-сборки: отсутствие проверенного worker build record должно останавливать сборку.
- Включить worker, его происхождение, необходимые лицензии и build binding в allowlist ZIP; обновить независимый verifier и диагностику.
- Сохранить атрибуции WarpScout/Android и историю исследований там, где действительно использованы их наработки.

**Готовность:** новый проверенный пакет запускается из пустой распакованной папки, не требует warpscout.exe и не принимает подменённый worker даже при пересчитанном локальном manifest. Наличие SHA не называется подписью.

### C. Подтвердить новую цепочку подключения

**Файлы:** `warp_discovery.rs`, `warp_probe.rs`, `warp_connection.rs`, существующие diagnostic CLI/smoke, `docs/validation/production-connection.md`.

- Проверить один успешный H2-путь через новый Rust consumer и mihomo, затем смешанный поиск WG/AWG/H3/H2.
- Проверить холодную регистрацию, повторное использование обеих семей, отсутствие экспорта ключей в scanner files, argv, environment и публичные события.
- Проверить медленное чтение событий, ошибку записи каталога, отмену при регистрации/поиске/проверке и сбой worker.
- Для worker и mihomo подтвердить завершение OS-процесса и освобождение владения; terminal event сам по себе недостаточен.

**Готовность:** есть новая native-запись успешной полной цепочки, точного ручного отказа без подмены, безопасной отмены и восстановления исходного состояния.

### D. Проверить матрицу протоколов и качество выбора

- Индивидуально ограничить поиск WG, AWG, H3, H2; повторить с общим разрешённым набором.
- Для каждого записать endpoint, параметры, внешнее семейство, handshake/HTTP/HTTPS и отдельно UDP.
- Использовать одинаковые цели и сопоставимые методы; измерять время первого рабочего результата и полной проверки таблицы отдельно.
- Провести ограниченные повторные проверки отказов. Не объявлять неудачный транспорт глобально заблокированным по одной сети.
- Для неподтвердившихся WG/H3 потребуется подходящая другая сеть или контролируемый протокольный стенд; текущий отказ остаётся видимым в отчёте.

**Готовность:** каждая строка матрицы имеет фактический результат и предел доказательства. Адаптеры, которые есть в коде, но не прошли внешнюю проверку, обозначены отдельно.

### E. Проверить разделение приложений

**Инструменты:** `tropa-routing-fixture.rs`, `scripts/{test-tropa-routing.ps1,tropa-routing-phase.ps1,tropa-routing-echo.py}`, `warp_smoke.rs`, правила `config/tropa.rs`.

- Повторить выбранный/прямой IPv4 TCP на актуальном пакете, включая одинаковые имена EXE из разных папок.
- Проверить короткие соединения и длительные сокеты, запуск до/после включения TUN, дочерние процессы и собственную тестовую службу.
- Проверить UDP burst, новые UDP sockets и постоянный UDP socket не менее пяти минут, с nonce и наблюдаемым внешним адресом на управляемом responder.
- Раздельно проверить внешние IPv6 endpoints и IPv6-трафик внутри туннеля.
- Проверить Firefox/Chrome, DoH, QUIC, существующие и новые браузерные соединения; подтверждать правила/outbound вместе с внешним путём.

**Готовность:** baseline / connected / after подтверждают смену пути только у выбранного приложения и возврат после отключения. Нет потерянных маршрутов, DNS и proxy-настроек. UDP DNS и loopback не закрывают внешний UDP-пункт.

### F. Проверить устойчивость и выход

- Не менее **20 последовательных подключений/отключений** на актуальной сборке с проверкой передачи данных и очистки, а не только нажатий кнопки.
- Не менее **60 минут непрерывной сессии** с контрольным TCP/UDP-трафиком по доступным проверенным направлениям.
- Отмена поиска, выход при регистрации/подключении, зависание/сбой worker и mihomo, недоступность интернета.
- Сон/пробуждение и смена сети; health monitor отличает передачу данных от живого PID.
- Крестик сохраняет туннель в трее; явный выход завершает собственные ресурсы. При неподтверждённой очистке — ошибка и запрет конфликтующего запуска.
- Сравнить процессы, временные credentials, маршруты, адаптеры, DNS, proxy и службы до/после. Чужие ресурсы не останавливать и не удалять.

**Готовность:** сохранены результаты каждого цикла, длительного сеанса и сценариев восстановления на конкретных версиях бинарников.

### G. Закрыть portable и чистую Windows

- Зафиксировать поддерживаемые Windows и CPU по всем компонентам; текущий mihomo требует x86-64-v2.
- Решить WebView2 без скрытого установщика. Предлагаемый путь для полностью автономного комплекта — поставляемый Fixed Version Runtime после проверки условий Microsoft; такой комплект будет больше. Наличие системного Evergreen отдельно не доказывает автономную поставку.
- Проверить UAC принят/отменён, чистую Windows, стандартную учётную запись, пути с пробелами/кириллицей, перенос и обновление папки.
- Проверить отсутствие скрытых зависимостей от `.tools`, developer PATH, установленного Rust/Go, старой папки и постоянно установленной службы.
- Описать перенос регистрации: копия папки с реквизитами остаётся копией того же устройства. Новую регистрацию создавать явным сбросом либо на чистой папке, не выдавая копирование за регистрацию нового устройства.

**Готовность:** реальный запуск из распакованной папки на чистой согласованной Windows и понятная инструкция, соответствующая фактическим зависимостям.

### H. Завершить лицензии, происхождение и обновления

- Для фактических файлов поставки сверить версии, ревизии, module/lockfile graph, source archive, хэши и notices.
- Закрыть соответствующие исходники Tropa/mihomo и все условия применимых GPL/MIT/прочих лицензий. Для mihomo с `vcsModified=true` получить точные изменения либо пересобрать из известного дерева.
- Проверить встроенный Wintun, fonts, Rust/frontend/Go transitive dependencies и выбранный WebView2-комплект.
- QUIC I1: исходный генератор с дополнительными ограничениями не копировать до разрешения вопроса. Оценить независимый вариант через уже используемый quic-go с собственным локальным capture; это отдельная реализация и проверка, не автоматическое закрытие лицензии.
- Проверить Authenticode каждого EXE/DLL и явно записать NotSigned там, где подписи нет. Для подписанного выпуска нужен сертификат/доверенный signing-процесс.
- Зафиксировать процесс обновления: закрепить новую версию → проверить конфигурацию/wire/API → protocol/routing/lifecycle regressions → новый source-bound комплект. Самостоятельное обновление компонентов без проверки совместимости не добавлять.

**Готовность:** нет необъяснённых бинарников и незакрытых обязательств фактической поставки. Хэши, лицензии, исходники и подписи описаны как разные свойства.

### I. Отдельные игровые измерения и группы процессов

Этот новый подсистемный этап начинается после проверки сетевой основы и получает отдельные design/spec и implementation plan.

- Пользователь явно задаёт игру/направление измерения; обычное подключение от этого не зависит.
- Для DIRECT и уже проверенных профилей используются одна цель, метод, время выборки и понятные метрики: RTT, jitter, loss, разрывы. DNS/endpoint ping не называется игровым ping.
- Не менять endpoint активной игровой сессии автоматически. Предлагать результат для следующего подключения или явного переключения.
- До рекомендаций для игры определить владельцев соединений: игра, launcher, authentication helper, anti-cheat service; проверить собственные synthetic service/process сценарии раньше реальных античитов.
- Проверить официальные правила конкретной игры. Сравнить DIRECT / весь компьютер / выбранную группу только после отдельного разрешения на запуск игры и античита.
- Не проксировать системный антивирус автоматически; не обещать отсутствие санкций или обязательное улучшение задержки. Неопознанный System/driver traffic остаётся непроверенным.

**Готовность:** отдельная воспроизводимая функция измерений с явными ограничениями и подтверждённой принадлежностью трафика для каждой рекомендованной группы процессов.

### J. Финальная поставка, сверка цели и уборка

- После исправлений собрать новый обычный portable ZIP из актуального source snapshot; диагностические features/EXE в него не включать.
- Проверить archive allowlist, binary/source/worker binding, версии, notices, отсутствие регистраций, настроек, логов и warpscout.exe.
- Проверить именно этот распакованный ZIP, а не другую папку с похожим EXE. Предыдущие native-доказательства привязывать к их точным сборкам.
- Составить итоговую матрицу всех 12 требований с исходником, командой/прогоном, артефактом и статусом. Не заменять незавершённый обязательный пункт общим числом unit-тестов.
- Сначала перечислить воспроизводимые промежуточные файлы, которые можно удалить, и сохраняемые исходники/пользовательскую работу/исследования. Затем выполнить адресную уборку; историю и evidence не удалять вслепую.

**Готовность:** актуальный архив и итоговый отчёт подтверждают каждое требование; незакрытые внешние условия не скрыты за `publicReleaseReady=true`.

## 6. Зависимости и порядок

Основная последовательность: **A → B → C → D → E → F → G → I → J**. Аудит **H** ведётся при изменениях компонентов и должен завершиться до окончательной публичной поставки. Рабочий локальный ZIP для native-проверок создаётся уже в B; финальный архив J создаётся после последующих исправлений.

При недоступном внешнем стенде продолжать независимые задачи: локальные protocol/session tests, упаковку, audit, UI и lifecycle fault checks. Ни IPv6, ни внешний UDP не объявлять пройденными по косвенным результатам.

## 7. Соответствие исходной цели

| Требование цели | Где закрывается | Текущий итог |
| --- | --- | --- |
| 1. Собственный поиск без WarpScout CLI | A, B, C | Production CLI/report/export путь удалён; source-bound ZIP `l` проверен без WarpScout. Обычный EXE с пустым data успешно подключился через H2/TUN; дальнейшие fault/mixed проверки открыты |
| 2. WG/AWG/H3/H2, tuning, семьи адресов и identities | A, C, D, H | Адаптеры, tuning и раздельные identities реализованы. WG/H3 не передали данные в текущих внешних опытах; outer/inner IPv6 и QUIC I1 не закрыты |
| 3. Рабочие кандидаты и проверка через mihomo | A, C, D | Чистый core: standalone H2/AWG HTTP/HTTPS и UDP DNS; ordinary автоматический H2/TUN с холодными registrations/catalog и точный ручной H2 также прошли. Ранний отказ → расширение и полный mixed/fault-набор открыты |
| 4. Авто/точный ручной выбор, ограничения и свежесть | A, C, D | Реализованы saved/canonical ordering, tuning, policy-aware handoff и resumable expansion; свежая проверка обязательна. Native early-failure → expansion → success и текущий точный ручной отказ ещё нужны |
| 5. Разделение EXE TCP/UDP/IPv6/браузеров | E | Ordinary `l`: exact-path IPv4 HTTP/HTTPS TCP с одинаковыми EXE; GUI picker и Firefox selected / Chrome direct off-on-off, включая один Firefox HTTP/3-запрос. DoH, произвольный UDP, IPv6, длительные сокеты и явный тип пути открыты |
| 6. Устойчивость и очистка | C, F | Worker OS-exit, backpressure и persistence-error evidence есть. Отдельный diagnostic EXE: 1 + 20 production-path H2 TUN циклов с selected/direct HTTPS и полной очисткой прошли. 60 минут, сон/смена сети, системные аварии и другие протоколы открыты |
| 7. Portable UX, tray, отсутствие утечек | B, C, F, G | На ordinary `l` подтверждены крестик → tray с живым H2 и явный Exit с остановкой ядра/TUN и восстановлением сети. Полный набор смены настроек, ошибок/выхода во время операций остаётся |
| 8. Чистая Windows и перенос | G | Worker из ZIP `l` проверен до/после переноса в пути с кириллицей и пробелами. Это не чистая Windows, GUI, WebView2, обновление или отказ UAC |
| 9. Лицензии, исходники и подписи | H | Core source/clean build/local repeatability, worker source binding, notices и embedded bytes подтверждены. Plugin terms, полные corresponding sources/лицензии и подписи не закрыты |
| 10. Отдельные игровые измерения | I | Не реализованы; следуют после приёмки основы. Запуски игр/античитов требуют отдельного согласования |
| 11. Актуальный ZIP и аккуратная уборка | B, J | ZIP `l` независимо проверен; его обычные H2 TUN/tray/Exit и отдельное IPv4 TCP-разделение приняты в указанном scope. Полная native-матрица и финальная уборка не завершены. Archive ignored, legacy workflows untracked |
| 12. Доказательство каждого требования | J | Матрица обновлена по фактическому scope evidence. Общая цель не выполнена; исходники/тесты не заменяют native, clean-Windows и внешние стенды |

## 8. Какие внешние возможности понадобятся

| Возможность | Для чего | Что известно сейчас |
| --- | --- | --- |
| Управляемый внешний TCP/UDP responder | Наблюдаемый путь и ответы произвольного UDP | У пользователя нет сервера; DNS и локальный echo его не заменяют |
| Рабочая внешняя IPv6-связность | Outer IPv6 и inner IPv6 как разные проверки | Не подтверждена |
| Чистая Windows / тестовая VM | Реальные OS/CPU/WebView2/UAC зависимости | Результата такого стенда нет |
| Участие пользователя в отдельных системных действиях | UAC, сон/пробуждение, смена сети при необходимости | Собственные тесты разрешены; фактический UAC иногда требует человека |
| Сертификат и signing-процесс | Подписанный выпуск | Подтверждения наличия нет; SHA-256 не является заменой |
| Отдельное разрешение на конкретную игру/античит | Игровая совместимость и группы процессов | Общего разрешения на такие запуски нет |

Zapret остаётся включённым. Официальный WARP и его настройки не менять без отдельного согласования. Сторонние скачанные проекты остаются источниками для изучения, их приложения не запускать.
