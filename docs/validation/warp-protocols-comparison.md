# WARP: сравнение с zapret и без — 27 октября 2026

Пользователь поочерёдно подтвердил отключение и включение zapret на роутере. В обоих случаях официальный WARP оставался Disconnected, прямой Cloudflare trace — `warp=off`. Настройки роутера агентом не менялись. Исходные версии: неизменённый WarpScout 0.16.1 и pinned mihomo v1.19.33.

Подробный первый прогон и метод: [проверка без zapret](warp-protocols-zapret-off.md).

## Парные результаты

«Да» в таблице означает три успешных HTTPS Cloudflare trace с `warp=on` и три валидных DNS A-ответа по UDP через mihomo. Системные маршруты/TUN не менялись; единственный MATCH rule направлял запросы в испытуемый proxy без DIRECT fallback.

В прогоне с zapret повторены шесть конкретных наборов AWG из первого прогона. Равенство всех полей amnezia-wg-option, включая I1, проверено программно; identity, endpoint, keepalive, DNS и allowed-ips сохранены. MASQUE использовал те же EC-ключи тестовой регистрации и сравниваемые endpoint/SNI. Для стандартного HTTP/3 без zapret имеется отрицательный stock scan по всем 14 адресам/портам, а не отдельный запуск mihomo; это различие метода обозначено явно.

Это последовательные сетевые измерения. Они не устанавливают причинность каждого отличия и не доказывают, что DNS I1 всегда ломается при zapret. Публичный anycast, время, пакетная фильтрация и сессионное состояние могут влиять на результат. Утверждение ограничено фактически проверенными профилями и двумя подтверждёнными состояниями роутера.

## Значение для разработки

Нельзя ограничивать Tropa обычным WG или фиксированным endpoint. В этой сети уже подтверждены независимые от zapret варианты AWG, MASQUE HTTP/3 и MASQUE HTTP/2 с подобранным SNI. Для первого рабочего сценария разумны AWG standard/QUIC как первые кандидаты и оба MASQUE с проверенными параметрами как дополнительные варианты; оптимальность для конкретной игры ещё не измерялась.

Профиль должен сохранять transport + endpoint + конкретные параметры AWG/I1 или MASQUE/SNI, а не только IP:port. После обнаружения нужно проверять профиль тем же mihomo, который будет держать игровое соединение. Повторный запуск обязан использовать сохранённые параметры. При необходимости менять кандидат — до игровой сессии либо по явному действию пользователя.

Для MASQUE нужна отдельная EC-регистрация, которая ещё не добавлена в автоматическую регистрацию Tropa. Успешный тест с оригинальным native-account WarpScout не заменяет реализацию этого backend. Нужны также модель профиля, lifecycle подключения, изоляция upstream updater перед GUI и интеграция с интерфейсом. В ходе текущего испытания production-код приложения не менялся.

## Проверка завершения

Оба состояния: оставшихся scanner/core процессов — 0, временных экспортов/runtime-файлов с ключами — 0. Адаптеры, default routes и ProxyEnable после каждого прогона совпали с его исходным снимком. Оригинальные exe не изменялись. В конце zapret включён пользователем, официальный WARP остаётся отключённым.

Материалы первого прогона: `.artifacts/protocols-zapret-off/`. Материалы сравнения: `.artifacts/protocols-zapret-on/wg-stock-result.json`, `comparison-results.json`, `cleanup.json`; воспроизводимый сценарий `.artifacts/test-zapret-on-comparison.py`. Реальные реквизиты остаются только в исключённой secrets-папке и не копируются в документацию.

Это функциональные испытания коротких HTTPS и DNS UDP запросов. Длительная игровая сессия, восстановление после обрыва, нагрузка, потери и фрагментация ещё не проверены. Ни адреса, ни маскировочные параметры не гарантируют работу в любой сети.
