# Ограничения выбора серверов — 28 октября 2026

Исполнение вехи 3 [общего плана](../superpowers/plans/2026-10-28-tropa-next-milestones.md). Реализованы настройки и проверки кода; нативный прогон Tropa/TUN отложен пользователем. Скачанные WarpScout/Oblivion и их бинарники не запускались.

## Поведение

В portable `tropa.yaml` добавлена `selectionPolicy`: разрешённые транспорты, include/exclude узлов и include/exclude стран узлов. Пустые positive-списки означают все значения. Исключение имеет приоритет; полностью исключённый positive-список отклоняется до поиска. Коды нормализуются в uppercase, дубликаты удаляются, каждый список ограничен 64 значениями, узел — три ASCII-буквы, страна — две. Вложенные неизвестные поля policy отклоняются. Preferences без нового поля совместимы, default policy не добавляет обязательное поле в прежний wire-roundtrip.

Редактор находится в раскрываемом разделе «Ограничения подключения» панели серверов. Фильтр таблицы и фильтр протокола меняют только видимые строки. Они не являются сетевой policy, не удаляют профили и не меняют ручной выбор.

Политика применяется к флагам WarpScout (`-node`, `-exclude-node`, `-country`, `-exclude-country`), порядку допуска сохранённых кандидатов, ручному выбору и свежей проверке перед TUN/Connected. Выключенный транспорт не запускается через другой AWG preset. Изменение policy сохраняет pinned profile, даже если он теперь запрещён; интерфейс показывает конфликт, подключение отклоняется без переключения в Automatic. Сохранение policy не меняет уже работающую сессию.

Недоступный вручную выбранный сервер и запрещённый сервер различаются: обычный отказ его transport validation остаётся сетевой ошибкой, конфликт или отсутствие обязательной metadata — `policyRestricted`.

## Два разных поля страны

В observations и frontend вместо неоднозначного `country` используется `exitCountry`. Старые записи с `country` читаются через deserialize alias исключительно как страна выхода. Новое `nodeCountry` отдельно допускает отсутствие данных и никогда не заполняется из exitCountry.

Проверено по исходникам WarpScout v0.16.1 (`9e2ce9570625757ba24b390ad680dccd5e7f2707`): `meta.go`, `discovery.go`, `geo.go`. Он использует `https://speed.cloudflare.com/meta`, поля `colo.iata` и `colo.cca2`; верхнеуровневое `country` — другая сущность. Дополнительно загружен исходник `meta.go`, без выполнения. Аргументы CLI сверены с закреплёнными flags/README.

Tropa получила ограниченный по времени/размеру запрос structured metadata через тот же локальный proxy client, которым проверяется WARP. Из ответа сохраняются только код узла и страна узла; IP, тело ответа и регистрационные секреты не экспортируются. При недоступности metadata обычная проверка без географических ограничений может продолжаться. При ограничениях неизвестные обязательные поля не разрешают подключение.

Старую metadata разрешено использовать только для отбора кандидата на повторную проверку. Перед TUN используются свежие данные probe; после включения TUN, до Connected, нужные географические условия проверяются ещё раз через действующий путь. Ни старый кэш, ни страна выхода не заменяют этот шаг. Старые scanner ping/loss сохраняются со своим исходным временем, а не объявляются новыми измерениями. При изменении узла свежая metadata не перезаписывается старой.

## Проверки и границы

До реализации запущен regression `selection_policy_survives_preferences_roundtrip`: он упал, поскольку прежние preferences игнорировали новое поле. После изменения настройки сохраняются, нормализуются и повторно читаются. Добавлены проверки include/exclude DME/HEL/ARN, стран DE/NL, неизвестных полей географии, противоречивых/слишком длинных списков, построения CLI, сохранения конфликтующего ручного выбора и миграции country → exitCountry без выдумывания nodeCountry.

Проверки frontend подтверждают наличие разных controls для policy и таблицы, сохранение предупреждения о конфликтующем pin и отсутствие изменения исходного каталога при локальном фильтре. Это не заменяет GUI interaction testing.

Итоговый повторный прогон после последних изменений завершился успешно: 407 Rust library tests, 52 frontend tests, TypeScript, ESLint изменённых файлов без предупреждений и production-сборка Vite. Lint warning fast-refresh устранён переносом общей default-константы в utils. Эти проверки не запускают Tropa и не доказывают работу нативного туннеля.

Визуальный preview не проверен: browser tool дважды завершился с `trusted Node process exited unexpectedly`; локальный Vite preview был остановлен. Сам desktop EXE, TUN, настоящий запрос metadata через WARP, переключение сети и UAC не запускались.

Веха 3 целиком не объявляется завершённой: ещё нужно маркировать сетевой контекст/устаревание наблюдений и выполнить отложенные нативные проверки. Гарантия неизменной страны выходного IP не даётся. Следующий независимый участок — планировщик с отдельными бюджетами WG/AWG; прежний последовательный перебор AWG в этом пакете ещё не заменён.

## Дополнение: отдельный режим поиска

В панели серверов появился одноразовый выбор «Все разрешённые / WireGuard / AWG / MASQUE HTTP/3 / MASQUE HTTP/2». Он передаётся в backend отдельно от фильтра таблицы. Поиск сужает копию постоянной policy, сохраняет её географические ограничения и не разрешает исключённый транспорт. Настройки и ручной выбор сервера не перезаписываются; последующее обычное подключение использует постоянную policy. Backend отклоняет scoped-параметр вне операции обновления каталога.

Regression-тесты проверяют сохранение исходной policy, запрет обхода ограничений и независимые элементы управления поиском и таблицей. После изменения прошли 444 Rust library tests, 63 frontend tests (15 файлов), TypeScript, scoped ESLint, production Vite build и portable cargo check. Последний выполнен после завершения Vite: одновременная проверка читала пересоздаваемый dist и завершилась ошибкой отсутствующего asset; последовательный повтор успешен.

Tropa, UAC, TUN и сторонние VPN/scanner executables не запускались. Реальная сеть, интерактивный desktop UI и нативное завершение процессов этими проверками не подтверждены.

## Дополнение: возраст измерений

Панель отдельно показывает возраст последней успешной runtime-проверки и замеров WarpScout. До 15 минут — «недавно», начиная с 15 минут — «устарели»; отсутствующие, некорректные и будущие timestamps не считаются свежими. Обновление пометок раз в минуту не делает новых сетевых запросов. Текущая реализация не определяет смену сети; подсказка явно указывает необходимость повторной проверки после неё. Полная привязка наблюдений к сетевому контексту остаётся невыполненной частью вехи 3.

До изменения regression-тесты падали на отсутствии функции классификации возраста и пометок в отрисованной таблице. После изменения проходят сценарии свежего runtime/старого сканера, отсутствующей даты и сдвига часов вперёд. Это не проверка GUI в WebView и не нативная проверка сети.

Финальный прогон этого изменения: 65 frontend tests в 15 файлах, TypeScript, ESLint четырёх изменённых frontend-файлов без предупреждений, Vite production build и последовательный portable cargo check завершились с кодом 0. Backend в этом дополнении не менялся; предыдущий прогон 444 Rust tests относится к реализации отдельного поиска. Никакие Tropa/VPN-процессы для проверки не запускались.

## Исправление: качество проверенных профилей

Воспроизведено расхождение UI/backend: при противоположных результатах WarpScout и собственной проверки Tropa таблица «По качеству» выбирала scanner-favourite, а `WarpObservation::compare` — runtime-favourite. Frontend предпочитал tunnelLossPercent/tunnelPingMs даже для verified rows, тогда как backend сравнивает failed/samples, median_ms, jitter_ms и ID.

Для строк с runtime-наблюдением quality теперь использует долю отказов Tropa, затем runtime median и jitter; scanner-only строки сохраняют собственные метрики и группировку ниже проверенных. Нет подстановки scanner-успеха вместо отсутствующей runtime-метрики. Явная сортировка «По задержке» по-прежнему показывает сначала scanner tunnel RTT при наличии, а не переименовывает DNS RTT в игровой ping. Существующие приоритеты сетевого контекста при перепроверке кэша, policy, manual pin и сам выбор подключения не менялись.

Новый regression сначала упал на противоположном порядке двух verified rows, затем прошёл. Итог: 68 frontend tests в 15 файлах, TypeScript, scoped ESLint и Vite production build завершились успешно. Backend-код не менялся; native tests не запускались. ZIP `Tropa-bound-release-2026-10-28-a.zip` сохранён как предыдущий артефакт и этого последующего frontend-исправления не содержит; его build record относится к сохранённому snapshot, а не новым source/dist.
