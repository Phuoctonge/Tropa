# Автоматическая регистрация WARP: проверка реализации

Дата: 27 октября 2026 года. [Согласованный проект](../superpowers/specs/2026-10-27-automatic-warp-design.md), [план](../superpowers/plans/2026-10-27-automatic-warp.md).

## Результат

Ручной импорт JSON, замена файла и удаление регистрации убраны из интерфейса и Tauri IPC. Настройки показывают состояние устройства и подтверждаемый «Сбросить регистрацию». Лицензионного ключа и ручного ввода приватных ключей нет.

Backend предоставляет `ensure_warp_registration`: при наличии записи возвращает её статус без HTTP, при отсутствии создаёт X25519-пару, регистрирует публичный ключ прямым запросом Cloudflare и включает WARP. `reset_warp_registration` создаёт новую регистрацию и заменяет старую только после успешных ответов и атомарной записи. Обе операции и чтение статуса сериализованы config-write lock. Ответы frontend содержат только status/hasIpv6, ошибки фиксированы, tracing skip_all. Чтение статуса не вызывает регистрацию.

Копии находятся в `data/secrets/warp-account.json` и промежуточном `warp-pending.json`. Если PATCH или финальное сохранение не удались, следующая попытка использует сохранённую промежуточную запись. Обычный ensure продолжает использовать прежнюю основную запись, если она есть. Остаточный pending после успешного commit распознаётся по ID и очищается перед новым сбросом. Создание/сброс не удаляет прежнее устройство на сервере Cloudflare. Если ответ POST или первое сохранение потеряны, возможно неиспользуемое удалённое устройство; автоматического повтора POST нет.

Протокол проверен по [WarpScout register.go, commit 9e2ce95](https://github.com/vernette/warpscout/blob/9e2ce9570625757ba24b390ad680dccd5e7f2707/register.go). Реализация использует прямой HTTPS, без proxy/relay/redirect. Таймаут подключения 5 секунд, запроса 15 секунд, тело ответа ограничено 64 КиБ. Стороннее реле молча не включается при недоступности API.

Добавлена прямая зависимость `x25519-dalek =2.0.1` для совместимой генерации публичного ключа с сохранением приватного. Cargo.lock дополнен её криптографическим деревом (пять новых packages); версии прежних packages не обновлялись, pnpm lock не менялся.

## Выполненные проверки

- **366 Rust-тестов прошли**, включая прежние проверки хранилища и две новые регрессии. Workflow проверяет однократное создание, повторное использование, неудачный сброс с сохранением прежних байтов, восстановление pending, остаточный pending после commit и восстановление повреждённого основного файла через reset.
- При финальном аудите воспроизведены и исправлены два отказа восстановления: повреждённый pending блокировал reset, а ответ 404 при активации оставлял вечную попытку использовать непригодную запись. Для обоих сначала получено падение теста, затем полный набор прошёл после исправления. Теперь явный reset восстанавливает повреждённый pending, а 401/404/410 очищают его без автоматического нового POST. Основная запись остаётся сохранной.
- Независимое read-only ревью проверило HTTP/ключи, порядок сохранения, команды и frontend. После исправлений повторно проверены восстановление pending и окончательный отказ API; оставшихся существенных замечаний нет. По результату ревью проверен исходный код reqwest 0.13.5 и явно задана политика `retry::never()` вместо встроенных повторов протокола.
- Локальный HTTP-сервер проверяет POST/PATCH, публичный ключ в запросе, соответствие сохранённой приватной паре, Bearer token только в запросе активации. Проверены отказ API, некорректный JSON, превышение 64 КиБ и отсутствие ответа сервера в ошибке. В тестах используются синтетические записи; запросов регистрации к Cloudflare не было.
- **45 frontend-тестов прошли**, TypeScript и ESLint без ошибок.
- Headless Chrome на отдельном `tropa-preview.html`: отсутствие импорта и полей ключей, объяснение первого подключения, подтверждение/отмена сброса, busy-блокировка, успех, ошибка с прежним состоянием, восстановление после ошибки чтения, оба возврата «Назад», компактная ширина 320 px. Повторно проверены темы/основная навигация. Операции preview синтетические; реальный native backend браузером не запускается.

В `.artifacts/` сохранены журналы `auto-warp-workflow-red.log`, `auto-warp-workflow-green.log`, `auto-warp-http-red.log`, `auto-warp-http-green.log`, `auto-warp-pending-red.log`, `auto-warp-rejected-red.log`, `auto-warp-backend-tests.log`, `auto-warp-ui-red.log`, `auto-warp-ui-green.log`, `auto-warp-typecheck.log`, `auto-warp-lint.log`, `auto-warp-frontend-tests.log`. ## Практические границы

Главный переключатель остаётся недоступным: ensure готов как первый шаг координатора, но не подключён к несуществующему туннелю. Страница не создаёт устройство при открытии, отдельной обязательной кнопки регистрации нет. Сброс существующей/нечитаемой регистрации доступен как явное действие пользователя.

Реальные регистрация Cloudflare, передача данных через WARP, игровой UDP и нативный запуск не проверялись. До native smoke требуется изоляция updater и сетевого старта upstream. До включения туннеля координатор должен запрещать сброс активной/восстанавливаемой сессии. Portable ZIP для распространения пока не создан.
