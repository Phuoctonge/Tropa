## Что WarpScout действительно умеет

1. Четыре режима: `wg`, `awg`, `masque` (CONNECT-IP поверх QUIC/UDP), `masque-h2` (CONNECT-IP поверх TLS/TCP). AWG standard/QUIC/STUN/SIP/DNS/random — варианты параметров одного AWG-транспорта, а не ещё шесть протоколов.
2. Для WG/AWG сначала определяются отвечающие порты, затем через настоящие туннели запрашивается `speed.cloudflare.com/meta`. Одна успешная инициация не считается достаточным доказательством полезного соединения.
3. `-P` добавляет измерения внутри туннеля и проверку устойчивости. По умолчанию используются серии из 10 echo; отдельно учитывается последовательность потерь в конце. Статус `torn down` — наблюдаемое поведение, не доказательство конкретной причины блокировки.
4. Пулы WG/AWG содержат 14 IPv4 `/24`; при `-sample 5` получается 70 случайно выбранных адресов до исключения неработающих. Это не обещание 70 подходящих подключений и не перечень физических серверов. Поиск всех портов может давать несколько строк одного IP.
5. `-node`/`-exclude-node` фильтруют узел; `-country`/`-exclude-country` — `coloISO`, то есть страну узла. `SEEN AS` — отдельная страна выходного IP. Существующий текстовый отчёт содержит страну узла в `NODE LOCATION`; текущая Tropa хранит её только строкой, не отдельным структурированным полем.
6. `-best` и `-conf` выбирают один результат; файл отчёта сохраняет рабочие строки, отдельные torn-down результаты и лучшие варианты по узлам. Это три разных представления; парсер не должен склеивать их в один список.
7. `find-junk` подбирает параметры AWG, `find-sni` — SNI для конкретного MASQUE H3/H2. Найденный SNI одного режима не гарантирует другой. `-speed` — отдельное последовательное измерение пропускной способности; высокий throughput не доказывает хороший игровой ping.
8. Экспорт `mihomo-json` поддерживает WG/AWG/MASQUE; H2 задаётся `type: masque` + `network: h2`. Приватные поля экспорта нельзя превращать в постоянную публичную таблицу.
9. Регистрация хранит отдельные WG и MASQUE реквизиты. MASQUE использует ECDSA P-256, отдельный ID/token и двухэтапное enrollment. Существующий WG private key нельзя передать вместо EC-ключа.
10. `register` при существующей WG регистрации может ротировать ключ; нельзя запускать эту команду как безвредную проверку при каждом старте. Нормальный запуск Tropa повторно использует сохранённую регистрацию.
11. Доступны дополнительные `-target`, sweep портов, IPv6 и WARP-in-WARP. Это расширенные сценарии; они не нужны для первой надёжной версии и не должны незаметно запускаться при обычном подключении.

## Ограничения, которые нельзя скрыть интерфейсом

- Endpoint Cloudflare — anycast. Сохранённые узел и страна являются наблюдением на момент проверки; закрепление IP не фиксирует навсегда город или страну выхода.
- TUN + `DIRECT` означает прямой outbound после обработки локальным ядром. Это не обещание, что невыбранный процесс вообще не проходит виртуальный адаптер.
- В выбранном режиме общий DNS сейчас идёт напрямую; системный DNS может выполняться общим Windows-процессом. Нельзя обещать, что абсолютно все DNS-запросы выбранной программы идут через WARP.
- Windows process lookup в закреплённом mihomo использует `GetExtendedTcpTable`, `GetExtendedUdpTable`, `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` и `QueryFullProcessImageNameW`. Это запрос сведений о сокете/пути, не DLL-инжект и не запись памяти игры. Ошибка определения процесса всё равно возможна.
- Ни WarpScout, ни mihomo, ни похожесть на коммерческий ускоритель не доказывают совместимость с каждым античитом. Нельзя обещать отсутствие банов или автоматически проверять игры на основном аккаунте пользователя.
- При HTTP/2 внешний TCP-транспорт может усиливать задержки при потерях. Наличие UDP внутри CONNECT-IP не делает этот режим лучшим для игры.

## Предлагаемая архитектура и порядок

Сохранить Tauri/React и ограниченный форк Clash Verge Rev; WarpScout оставить внешним закреплённым обнаружителем, mihomo — единственным runtime. Отделить identity, профиль, наблюдение качества, политику выбора, сканирование и активное соединение. Для MASQUE добавить отдельную identity и генерацию уже поддерживаемого outbound. Не добавлять usque.exe, второй сканер и собственный WFP-драйвер без воспроизводимого ограничения существующей схемы.

Альтернативы: глубокий Go-форк WarpScout упростит структурированные события, но увеличит сопровождение и не решит автоматически TUN-routing; новая собственная оболочка/драйвер потребует заново отладить жизненный цикл и portable-поставку. Сейчас их стоимость не оправдана подтверждёнными дефектами.

Первый этап — диагностические ошибки и UDP/IPv6 app-specific routing. Затем ограничения выбора и честное расписание WG/AWG. После этого MASQUE identity/runtime и включение H3/H2 в общий подбор. Далее устойчивость соединения, portable-выпуск и только отдельным продуктовым этапом измерения маршрутов для игр. Подробности: [план](../superpowers/plans/2026-10-28-tropa-next-milestones.md).
