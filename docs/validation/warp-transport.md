# Проверка транспорта WARP — 27 октября 2026

Проверка проводится отдельной developer-утилитой `tropa-warp-probe`, feature `tropa-probe`. Это проверка транспорта, а не готового подключения игры или главного переключателя Tropa.

## Реально выполнено

- Первый запуск создал и активировал собственную регистрацию Cloudflare через существующий backend. Запись сохранена в исключённой из Git `.artifacts/warp-live/data/secrets/warp-account.json`; pending-файл после активации отсутствует.
- Mihomo v1.19.33 принял конфигурацию WireGuard и открыл локальный mixed listener. Закреплённый SHA256: `0b4c7353057a78de8a09db445351aadec7d72a4f48adc7d99691f3c5ff74d3da`.
- Два запроса HTTPS через endpoint `162.159.192.1:2408` не прошли. Второй запуск завершился ошибкой соединения; в ограниченной диагностике ядра присутствуют сообщения handshake и timeout. Успешный WARP trace не получен. Эти данные не доказывают конкретную причину сетевого ограничения.
- После обоих запусков процесс mihomo отсутствует, временный `warp-probe-runtime.json` удалён. Сохранённая регистрация остаётся для повторных запусков.
- Формат регистрации и POST/PATCH сверены с WarpScout commit `9e2ce9570625757ba24b390ad680dccd5e7f2707`.
- Третий запуск проверил HTTPS и UDP независимо: HTTPS снова завершился ошибкой соединения, DNS по UDP не подтверждён. SHA256 файла регистрации до/после совпал (сам хэш и реквизиты не публикуются). Сравнение снимков адаптеров, default routes, ProxyEnable и активных core-процессов подтвердило отсутствие изменений; оставшихся ядер — 0.

**Результат:** регистрация и локальный запуск ядра подтверждены; работоспособный WARP-транспорт на выбранном endpoint в текущей сети не подтверждён. Не выдаём это за успешное подключение и не приписываем отказ конкретному фильтру без дополнительных данных.

## Проверки реализации

367 тестов Rust app-library прошли с `--locked --features clippy,portable,tropa-probe`. Регрессия DNS сначала воспроизвела принятие пустого ответа с ненулевым answer count, затем проверка усилена: требуются совпадающий вопрос example.com A/IN и полный A-ответ. Усечённый ответ отвергается.

После review исправлена остановка дочерних процессов при ошибке Windows Job Object и при timeout валидации конфигурации. Остановка подтверждается ожиданием завершения процесса. Диагностика ядра читается в память с лимитом 64 KiB; наружу выводятся только заранее заданные признаки ошибок, без строк лога, ключей и API identity.

## Границы

TUN выключен; порт слушает только localhost. Утилита не устанавливает службу, не меняет системный proxy и маршруты и не запускает Tauri startup/updater. Исходное состояние сети: default IPv4 route через 192.168.1.1, system proxy выключен, активного mihomo нет. Внешние VPN-адаптеры уже присутствовали до проверки.

Игровая маршрутизация, UAC, восстановление TUN, интеграция с главным переключателем и нативный GUI smoke ещё не проверены. До запуска GUI требуется изолировать upstream updater. Выбор игрового `.exe` уже реализован; обход ограничений и сканирование endpoint в этот срез не входят.
