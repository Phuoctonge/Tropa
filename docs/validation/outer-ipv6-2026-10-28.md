# Внешние IPv6 endpoint: реализация без нативного запуска

28 октября 2026. Изменения относятся к адресу подключения к Cloudflare. Они не доказывают прохождение пользовательского IPv6-трафика внутри туннеля или корректность UDP split tunneling.

## Источник ограничений

Закреплённый WarpScout v0.16.1, commit `9e2ce9570625757ba24b390ad680dccd5e7f2707`: `pools.go`, `masque.go`, `flags.go`, `discovery.go`, `report.go`. Источники прочитаны; сканер и загруженный код не запускались.

- WG/AWG: `2606:4700:d0::/48`, `2606:4700:d1::/48`, прежний список WG-портов.
- MASQUE HTTP/3: только `2606:4700:103::1`, `::2` и `2606:4700:104::1`, `::2`.
- MASQUE HTTP/2: `2606:4700:103::/48`, `2606:4700:104::/48`.
- MASQUE-порты: 443, 500, 1701, 4500, 4443, 8443, 8095. IPv4 allowlists сохранены.

Scope ID не допускается. IPv4-mapped IPv6 не расширяет разрешённые пулы. Для HTTP/3 не используется широкий HTTP/2 pool.

## Что изменено

`WarpEndpoint` и `WarpProfile` используют `SocketAddr`; builders WG/MASQUE получают `IpAddr`. IPv6 endpoint сохраняется и отображается как `[address]:port`, в поле `server` ядра передаётся сам адрес без скобок. Исключение внешнего адреса из TUN — один host `/32` или `/128`.

Сравнение IP в экспорте WarpScout выполняется после разбора адреса: полная и сокращённая IPv6-запись эквивалентны, другой IP/порт отклоняется. Export должен соответствовать запрошенному семейству; report не может смешивать семейства.

Формат каталога остаётся version 1: сериализация старого `SocketAddrV4` и новой IPv4-ветки `SocketAddr` даёт прежние JSON-байты для ID. Тест сравнивает старый способ вычисления ID с новым, затем проверяет ручной IPv4 pin после добавления более быстрого IPv6-профиля и сериализации каталога. Переписывать ID и заменять ручной выбор не требуется. Старые версии приложения, умеющие только IPv4, не смогут прочитать новый каталог с IPv6-записями; обратная совместимость с ними не заявляется.

Поиск разделён на отдельные CLI-вызовы: IPv4 без `-6`, IPv6 с `-6`. Все первичные задачи разрешённых транспортов/семейств идут до расширений. Существующее распределение бюджета учитывает обе семьи и отказы регистраций; при 180-секундном остатке тест подтверждает минимум 20 секунд каждой из восьми первичных задач. IPv4-проверки идут первыми. Automatic может выбрать другой проверенный профиль до запуска сессии, manual pin не заменяется, автоматического переключения во время сессии нет.

Локальная подсказка включает IPv6-поиск только при адресе `2000::/3` вне loopback/internal и принадлежащего Tropa интерфейса. Ошибка перечисления интерфейсов или отсутствие такого адреса оставляет прежние IPv4-задачи без затрат времени на IPv6. Это не проверка маршрута: адрес может существовать при недоступном внешнем IPv6. ULA/NAT66 и другие случаи без адреса из `2000::/3` сейчас не включают автоматический IPv6-поиск. Фактическую доступность по-прежнему должна подтвердить проверка конкретного кандидата.

В progress добавлено необязательное `addressFamily`, название preset не меняется. Интерфейс показывает протокол и IPv4/IPv6 независимо; результаты таблицы сохраняют bracketed endpoint и возможность ручного выбора.

## Проверки и границы

Падающие тесты воспроизвели IPv4-only отказ parser/runtime, отказ эквивалентной записи IP в export, отсутствие семейства в progress UI, отсутствие IPv6-задач в планировщике и допуск смешанного report. После исправлений прошли 457 Rust tests, 67 frontend tests, TypeScript, scoped ESLint, Vite build и locked/offline portable cargo check. Ни Tropa, ни WarpScout, ни VPN-ядро не запускались.

Нативные критерии вехи 10 остаются открыты: подключение WG/AWG/H3/H2 к IPv6 endpoint на подходящей сети; реальный fallback при недоступном маршруте; отсутствие петли TUN; очистка после отмены/выхода; поведение после смены семейства сети. Присутствие локального IPv6, unit-тесты и сборка этого не подтверждают.

Ранее созданный `Tropa-release-local-2026-10-28.zip` содержит предыдущий код и не включает эти изменения. Его не перезаписывали. Исторический source snapshot также сохранён; текущие исходники после этой реализации намеренно отличаются от него. Новый ZIP не объявляется готовым без новой сборки и проверки состава.
