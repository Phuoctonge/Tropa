# Сетевой контекст измерений — 28 октября 2026

Дополнение к вехам 3 и 7 [согласованного плана](../superpowers/plans/2026-10-28-tropa-next-milestones.md). Tropa, сторонние VPN/scanner executables, TUN и UAC не запускались.

## Реализованное поведение

`config/warp_context.rs` получает локальный снимок адаптеров через уже имеющуюся библиотеку network-interface. В fingerprint входят индекс, friendly name и unicast IP-адреса внешних адаптеров. Порядок перечисления и дубликаты не меняют метку. Loopback, unspecified/multicast и собственный адаптер с именем Tropa исключены. FriendlyName сверено по исходникам network-interface 2.0.5 для Windows, без выполнения библиотеки отдельно.

Случайная 32-байтовая соль существует только в памяти процесса; каталог хранит SHA-256, без исходных имён, IP, SSID или MAC. После перезапуска старые метки консервативно не совпадают. Ошибка чтения адаптеров, отсутствие пригодных адресов или невозможность получить случайную соль дают неизвестный контекст. В frontend передаётся только same/changed/unknown, сам fingerprint туда не попадает.

Проверка Tropa и измерения WarpScout имеют отдельные метки. Контекст снимается до и после соответствующей операции; при несовпадении метка не публикуется как подтверждённая. Повторный runtime probe сохраняет исходную метку/дату замеров сканера. Смена регистрации сбрасывает контекст только своего семейства; старые адреса и manual pin сохраняются для повторной проверки. Старые каталоги без полей контекста читаются как неизвестные, новые необязательные поля валидируются и сохраняются без изменения версии каталога.

При автоматическом подключении кандидаты с совпадающим контекстом проверяются раньше неизвестных и изменившихся; порядок качества внутри группы сохранён. Все кандидаты по-прежнему проходят runtime-проверку перед TUN. Ручной выбор не заменяется. Поиск и активная сессия не запускают автоматическую смену сервера из-за метки.

В таблице свежая дата не скрывает changed/unknown. Результат с changed считается устаревшим, unknown не объявляется свежим. Каталог перечитывается раз в 15 секунд вне поиска, раз в секунду во время поиска; это локальное чтение и перечисление адаптеров, без дополнительных интернет-запросов.

## Практические границы

Совпадение локальной конфигурации не доказывает неизменность сети: смена Wi-Fi с тем же адресом/именем адаптера, маршрута, gateway, DNS, правил роутера или состояния zapret может не изменить этот снимок. Между двумя снимками может произойти переход и возврат к прежней конфигурации. Изменение неиспользуемого адаптера или временного IPv6-адреса может, наоборот, консервативно сделать данные устаревшими. Это подсказка для порядка повторных проверок, не идентификация сети и не основание пропустить runtime validation.

Нативные проверки смены сети, сна/пробуждения, чтения реальных Windows-адаптеров при TUN и обновления WebView остаются отложенными. Вехи 3 и 8 целиком не закрыты.

## Доказательства

Regression-тесты сначала падали на отсутствующих полях/API, затем на неверной классификации свежего timestamp при changed-контексте. Отдельно воспроизведён оставшийся scanner context при смене регистрации: тест failed с Some(old fingerprint) вместо None; после исправления проходит.

Тесты используют синтетические адаптеры и каталоги: перестановка адаптеров/добавление Tropa не меняют fingerprint; изменение адресов/соли меняет; пустой снимок даёт None; неизвестный контекст не равен подтверждённому. Проверены сохранение разных runtime/scanner-меток, JSON roundtrip, порядок кэша и точный manual pin, сброс при смене identity, wire contract без fingerprint, раздельные статусы в отрисованной таблице.

Финальная проверка: 448 Rust library tests, 66 frontend tests (15 файлов), TypeScript, ESLint изменённых frontend-файлов, production Vite build и portable-feature cargo check завершились с кодом 0 и без compiler/lint warnings. Cargo check запускался после завершения Vite, чтобы не читать пересоздаваемый dist. Это подтверждение кода и сборки, не работоспособности нативного подключения.
