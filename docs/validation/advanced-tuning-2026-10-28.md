# Расширенный подбор: совместимость и управление временем

Продолжение согласованной вехи 7. Действие расширенного подбора подключено к интерфейсу отдельной кнопкой «Подобрать параметры». WarpScout и mihomo здесь изучались как исходники; скачанный код/EXE, UAC и TUN не запускались.

## Подтверждённые форматы закреплённых версий

WarpScout v0.16.1 `findjunk.go` печатает `warpscout.exe scan -proto awg -jc N -jmin N -jmax N` с необязательным `-i1`. Если I1 отключён, печатается `-i1 none`, а `wgconf.go::mihomoProxy` опускает поле `amnezia-wg-option.i1`. `findsni.go` печатает protocol-specific `-masque-sni HOST`; отсутствие флага означает consumer-masque.cloudflareclient.com. Найденный H3 SNI не подтверждает H2.

Pinned mihomo v1.19.33, commit `3f27ef39f8c96bbfbc8b0b9bb10f5c9ef60149d8`, `adapter/outbound/wireguard.go` содержит optional I1 string и записывает строку `i1=` в IPC только при непустом значении. AWG без I1 сохраняет JC/JMin/JMax и стандартные WARP headers; это не переименование в обычный WireGuard.

## Исправленная несовместимость Tropa

Раньше parser требовал строковое поле I1, а profile validation запрещала пустую цепочку. Две регрессии воспроизвели `Missing AWG init parameters` и `Invalid AWG init parameters` для допустимого no-I1 варианта.

Теперь отсутствующий I1 в scanner export нормализуется в пустую строку профиля. Явный пустой I1 даёт тот же профиль/ID; JSON round trip сохраняет его. Null, число, литерал `none` внутри JSON и неправильные/слишком длинные цепочки не становятся пустым значением. Ограничения JC/JMin/JMax/headers и endpoint остаются прежними. Runtime builder опускает I1 при выключенном пакете, сохраняя AWG junk parameters. Непустые цепочки продолжают проверяться и сохраняться; прежние ID непустых профилей не меняются.

После исправления прошли 463 Rust library tests и production portable-feature cargo check locked/offline. Это проверка разбора/профиля/config generation, не реальный handshake или обход ограничения сети. Предыдущий portable ZIP данного изменения не содержит.

## Следующая интеграция

Прямой `find-junk` выполняет неограниченное число раундов до threshold/interrupt. При принудительном завершении hidden Windows child по deadline утилита может не успеть напечатать лучший набор. `find-sni` печатает shell-like command, а не структурированный профиль. Эти команды нельзя слепо передавать shell или считать их handshake/ping успешной runtime-проверкой Tropa.

Для приложения использовать конечные задачи существующего `scan` adapter: AWG `-gen-junk -gen-i1 random` и no-I1 вариант; MASQUE — отдельные H3/H2 проходы с default SNI и кандидатами из pinned i1Hosts (www.apple.com, www.google.com, www.microsoft.com, cdn.jsdelivr.net). Это те же генераторы и SNI-кандидаты, но общий бюджет/отмена и сохранение промежуточных exports остаются у Tropa. Точные сгенерированные параметры берутся только из проверенного mihomo-json export, не из напечатанного command text.

Действие будет отдельным от Connect и обычного поиска. Нужно сохранить fair budgets по транспортам/семействам адресов, policy restrictions, независимость registration families, текущий manual pin, подтверждённую очистку дочерних процессов и последующую runtime validation. Не считать процент удачных scanner handshake игровым качеством или универсальным обходом DPI.

## Реализованная интеграция

Отдельное действие передаёт advanced=true через существующий IPC refresh_tropa_servers. Обычный поиск и Connect не включают подбор. WG-only ограничение отключает кнопку; backend также отвергает неподдерживаемый режим. Настройки ограничений и ручной выбор сохраняются. Прогресс различает подбор SNI H3/H2 и AWG random/no-I1.

Общий бюджет — 600 секунд. Первичные проходы ограничены 30 секундами, чтобы при двух семействах адресов осталось время на дополнительные варианты. Варианты MASQUE H3/H2 планируются отдельно. Реальная длительность и эффективность требуют будущей проверки сети.

Проверки после интеграции: 465 Rust library tests, 71 frontend test (16 файлов), TypeScript, scoped ESLint и Vite production build прошли. Ни Tropa, ни scanner/core, ни UAC/TUN для этих проверок не запускались. Исторический portable ZIP не содержит этих изменений; новый архив на этом шаге не создавался.

## Соответствие запрошенному варианту

Перед построением списка кандидатов проверяется соответствие транспорта, явно запрошенного MASQUE SNI и AWG init-mode: no-I1 требует пустого I1, random требует непустой допустимой цепочки. Чужой вариант возвращает Scanner/InvalidOutput. При этом конкретные случайные JC/JMin/JMax/I1 сохраняются из export, а не из seed. Регрессия включает допустимые разные AWG значения и отклонение неверного SNI/I1 для H3/H2 и обоих AWG режимов. После изменения прошли 466 Rust tests и production portable cargo check locked/offline. Реальные процессы VPN не запускались.
