# Протоколы WARP без zapret — 27 октября 2026

## Условия и метод

Пользователь подтвердил отключение zapret на роутере. Официальный Cloudflare WARP до и после испытаний: Disconnected. Прямой Cloudflare trace: `warp=off`. Параметры роутера принимаются по сообщению пользователя, его конфигурация агентом не менялась.

Использованы неизменённые официальные WarpScout 0.16.1 и mihomo v1.19.33 с ранее закреплёнными SHA256. Сканер запускался напрямую отдельным процессом; адаптер Tropa, GUI, TUN и системный proxy не использовались. Учётные данные — отдельная штатная регистрация WarpScout, созданная ранее через прямой Cloudflare API, включая его MASQUE device. Регистрация приложения Tropa не менялась.

Все четыре транспорта, поддержанные текущим WarpScout, проверены: WG, AWG, MASQUE HTTP/3, MASQUE HTTP/2. Для AWG проверены стандартный I1 и генераторы QUIC, DNS, STUN, SIP, random. Это конечная матрица поддержанных транспортов и представительных профилей; произвольные сочетания всех численных параметров и всех SNI не перебирались.

Основная команда: `warpscout scan -proto <protocol> -plain -best -no-report -sample 5 -timeout 3 -account <native-account>`, штатные 10 работников, лимит отдельного процесса 180 секунд. Для успешного кандидата затем запускался штатный `socks` на localhost и три HTTPS-запроса Cloudflare trace с обязательным `warp=on|plus`. WG/AWG сканировали по 5 адресов из 14 /24 пулов, всего 70 адресов; MASQUE использовал собственные пулы и порты.

Чтобы проверить ядро Tropa, кандидат повторно проверялся штатным сканером с `-target IP -port PORT -conf <secret> -conf-type mihomo-json`. Полученный единственный proxy включался в временную конфигурацию mihomo: loopback mixed listener, MATCH через этот proxy, TUN/DNS listener выключены, DIRECT fallback отсутствует. Требовались три HTTPS trace и три DNS A-ответа example.com от 1.1.1.1 по SOCKS5 UDP ASSOCIATE. Проверялись transaction ID, QR/RCODE/TC, вопрос и полный A RR. DNS RTT не называется игровым ping.

Оригинальный SOCKS WarpScout не поддерживает UDP ASSOCIATE; поэтому UDP проверен именно через mihomo. Сами оригинальные бинарники и их исходники не правились. Временные Python-сценарии управляют процессами и запросами; они находятся только в исключённой `.artifacts`, не являются production-кодом Tropa.

В AWG использованы штатные `jc=6`, `jmin=10`, `jmax=50`. Совместимые с Cloudflare WG headers не изменялись: `s1=s2=0`, `h1..h4=1..4`. Здесь AWG добавляет маскирующие начальные/junk-пакеты к совместимому WARP WireGuard; это не подключение к произвольному AWG-серверу с изменёнными заголовками. Генераторы создают новые I1 при каждом запуске; JSON-экспорт сохранял конкретный пакет, который затем использовал mihomo. Успех семейства random не означает проверку всех возможных случайных пакетов.

DNS I1 с фиксированным www.google.com дал неуспешный SOCKS-тест оригинального сканера, но после повторной проверки/экспорта успешно прошёл все проверки mihomo. Причина отличия SOCKS-пути не установлена. Такие результаты нельзя скрывать единственным зелёным статусом «сканер нашёл».

## Дополнительный find-sni

Применена штатная команда `find-sni -proto masque|masque-h2 -plain -timeout 3 -account <native-account>`, с лимитом 180 секунд. Порог сканера по умолчанию — 70%; источник результата учитывался независимо от exit 0.

- HTTP/3: стандартный consumer-masque.cloudflareclient.com — 0/14; www.apple.com, www.google.com, www.microsoft.com, cdn.jsdelivr.net — каждый 2/14. Порог 70% не достигнут. С www.apple.com затем отдельно подтверждён конкретный рабочий endpoint через SOCKS и mihomo.
- HTTP/2: стандартный SNI — 1/14; www.apple.com — 14/14. Порог достигнут, остальные SNI в этом запуске не понадобились. После этого отдельно подтверждён конкретный endpoint.

2/14 и 14/14 относятся к тестовой выборке IP:port, не к доле всех серверов Cloudflare. Успех после смены SNI показывает полезность параметра, но не устанавливает точную реализацию фильтрации провайдера. Нельзя обещать, что эти значения будут работать в любой сети.

## Завершение и границы

После всех тестов адаптеры, default routes и ProxyEnable совпали с исходным снимком. Официальный WARP остался Disconnected, прямой trace — `warp=off`. Оставшихся процессов scanner/core — 0; временных экспортов и runtime-конфигов с ключами — 0. Контрольные суммы обоих exe не изменились. Отдельная регистрация тестов сохранена только в исключённой secrets-папке.

Доказательства: `.artifacts/protocols-zapret-off/results.json`, `mihomo-results.json`, `control-results.json`, `cleanup.json`, отдельные stdout/stderr каждого запуска. Публичные exit IP пользователя и реквизиты не включены в этот документ.

Read-only review временных сценариев не выявил прямого fallback или ложного подтверждения UDP. Это короткие функциональные проверки HTTPS и DNS UDP. Игровой трафик, потери под нагрузкой, длительная устойчивость, MTU/фрагментация и снижение задержки не проверены.

## Следствия для Tropa

Подтверждённые направления — AWG с сохранением конкретных junk/I1 параметров и MASQUE h3/h2 с сохраняемым SNI. Выбранный mihomo v1.19.33 уже принял и выполнил эти режимы; менять ядро ради данного результата не требуется. Для production ещё нужны модель транспорта/профиля, регистрация MASQUE с отдельной EC-идентичностью, сохранение прошедших проверку параметров, lifecycle и GUI. Успех в испытаниях не означает, что текущий главный переключатель приложения уже подключает игру.
