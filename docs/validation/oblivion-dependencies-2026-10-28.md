## Подтверждённые детали

### warp-plus

В v1.2.6 `ipscanner/ping/warp.go:56` измеряет WireGuard handshake с выбранным IP и случайным WARP-портом. Такой RTT описывает установление обмена с endpoint; это не игровой ping и не проверка качества передачи данных.

`app/wg.go:20` отдельно проверяет передачу через usermode netstack: HTTP HEAD к test URL, ожидает HTTP 200. Это сильнее одного handshake, но без разбора WARP trace не доказывает `warp=on`, не измеряет UDP-потери или jitter. На этот критерий нельзя опираться как на полное доказательство готовности Tropa.

`app/app.go` перебирает внутренние режимы `t1`/`t2`, а `app/wg.go:108` передаёт `trick` в модифицированный WireGuard. Их нельзя автоматически приравнивать к AWG-профилям WarpScout либо объявлять самостоятельными протоколами. Детальный перенос этих преобразований пакетов в этом исследовании не выполнялся.

WARP-in-WARP строит два последовательных туннеля и две identity; Psiphon — дополнительная цепочка. Это отдельные режимы, а не гарантия нужной страны, низкой задержки или поддержки игрового UDP. До интеграции нужны сравнение с DIRECT/обычным WARP, проверка UDP, MTU, времени запуска и восстановления. Приоритет ниже надёжного базового подключения.

`warp/account.go:30` загружает локальную identity, при неудаче загрузки удаляет переданный cache directory через `os.RemoveAll(path)` и создаёт регистрацию заново. Не переносить такую реакцию на любую ошибку чтения: в Tropa различать отсутствие файла, повреждение, доступ и сетевой отказ; сетевой сбой не должен незаметно сбрасывать устройство. Лицензионный ключ WARP+ остаётся вне текущего пользовательского запроса.

### Masque-Plus

v2.9.0 — launcher для usque, не отдельная реализация MASQUE. `main.go:553` запускает `usque register`, `main.go:607` формирует `usque socks` с параметрами endpoint/SNI, DNS, initial packet size, keepalive, MTU и семейств трафика. Обнаружение поддержки произвольных параметров в launcher не доказывает их поддержку текущей версией mihomo.

Во время выбора кандидатов callback вызывает `internal/httpcheck/warpcheck.go`: запрос через SOCKS, HTTP 200 и поиск `warp=on` в теле. Это полезный пример проверки data plane. Разбор у них основан на substring; в Tropa нужен точный разбор trace, отдельные причины HTTP/timeout/no-WARP и доказательство прохождения через тестируемый outbound. HTTPS/TCP-проверка не заменяет самостоятельный UDP-тест.

В `internal/scanner/scanner.go` есть QUIC и TCP-TLS пробы. Успешный TLS handshake не доказывает MASQUE H2: в рассмотренном `createUsqueCmd` нет явного H2-переключателя. Не представлять найденную TCP-пробу как подтверждение рабочего H2-туннеля. Наши прежние отдельные H2/H3 проверки mihomo описаны в собственных протоколах испытаний и не подменяются этим выводом.

Launcher использует строки логов дочернего процесса и автоматически отправляет `y` в регистрацию. Tropa не должна связывать согласие пользователя и готовность соединения с таймингами stdin или свободным текстом логов. Регистрация — отдельная управляемая операция; обновление identity не должно быть бесконечным лечением любого сетевого отказа.

### Oblivion Helper

Dr-Bad v1.3.2 запускается с admin/root, встраивает sing-box и читает JSON рядом с EXE. Это показывает, что повышенный процесс может обслуживать TUN без обязательной постоянной службы; конкретные драйверы, восстановление маршрутов и аварийный выход всё равно требуют проверки на Windows.

`cmd/main.go:52,604–610`: фиксированный `127.0.0.1:50051`, обычный `grpc.NewServer()` без настроенных TLS/auth interceptors. В рассмотренном сервере не обнаружена авторизация клиента RPC. Loopback ограничивает сетевую доступность, но не идентифицирует вызывающий локальный процесс. Такую модель привилегированного управления копировать не следует. Если отдельный helper понадобится Tropa, проектировать контроль доступа Windows IPC, ограниченные команды, владение дочерним процессом и завершение вместе с владельцем. Сейчас новый helper не требуется.

### Актуальный Oblivion — отдельный проект

`bepass-org/oblivion` на `bd8d2ac0659ac7524504354f8756447e6a54ef92` содержит Flutter/Dart и Rust core, в том числе Windows-ветки, а не только исторический Android-клиент. Его нельзя смешивать с изученным Electron Oblivion Desktop.

`lib/data/services/mtu_probe.dart` содержит отдельный probe с DNS/QUIC-ответами, бюджетом по умолчанию 60 секунд, поиском размеров и Windows don't-fragment socket option. Это кандидат для диагностики случаев «handshake есть, данные зависают». Результат относится к пути до выбранного probe target; он не автоматически равен внутреннему MTU WARP. Перед применением учитывать overhead конкретного транспорта, IPv6-минимум, потери/фильтрацию и возможность неопределённого результата. Не добавлять минутный probe в каждое нажатие «Подключить».

`lib/data/models/tunnel_settings.dart` отдельно моделирует режимы split tunnel и пустой список onlySelected. Наличие модели/экрана не доказывает корректную Windows process routing; соответствующий runtime и нативные UDP/IPv6 проверки остаются обязательными.

## Влияние на план Tropa

Основной [план](../superpowers/plans/2026-10-28-tropa-next-milestones.md) сохраняется: диагностика → доказанный split tunnel TCP/UDP → независимые бюджеты поиска → MASQUE identity и H3/H2 → восстановление → portable release.

Уточнения для исполнения:

1. Разделять быстрый handshake RTT, in-tunnel RTT/потери и готовность сессии. В таблице не называть их игровым ping.
2. Не сбрасывать регистрацию при ошибке сети/чтения автоматически; сохранять возможность разобраться в исходной причине.
3. Для MASQUE использовать отдельную EC identity и существующий mihomo runtime. Не добавлять masque-plus/usque только потому, что они используются в другой оболочке.
4. MTU probe оставить отдельной диагностикой/исследованием после базовой UDP-проверки. По его результату не менять параметры активной игровой сессии скрыто.
5. Не добавлять постоянную службу, неавторизованный привилегированный RPC или исключения антивируса ради копирования чужой архитектуры.
6. Цепочки Psiphon/WARP-in-WARP рассматривать отдельно при измеренном ограничении; они не заменяют честный выбор WG/AWG/MASQUE.

Корневые MIT/GPL-лицензии этих компонентов рассматриваются независимо от ограничительной лицензии Oblivion Desktop. Перед переносом кода/поставкой бинарников проверить закреплённую версию, notices и транзитивные лицензии. Список Acknowledgements сам по себе разрешения на копирование не даёт. Этот анализ не подтверждает совместимость с античитами и не позволяет обещать отсутствие блокировок.
