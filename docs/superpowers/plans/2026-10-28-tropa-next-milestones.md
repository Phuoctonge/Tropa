# Tropa: подключение, поиск и надёжный portable-клиент — Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement one milestone at a time in the current session. Steps use checkbox syntax. This document authorizes no automatic game launches, public deployments, dependency upgrades or changes to a user's active connection. Do not start parallel agents unless separately authorized.

**Goal:** Довести существующую Tropa до проверенного portable WARP-клиента с выборочной маршрутизацией, автоматическим/ручным выбором подключения и WG/AWG/MASQUE H3/H2.

**Architecture:** Сохранить ограниченный форк Clash Verge Rev, Tauri/React, внешний WarpScout v0.16.1 и одно ядро mihomo v1.19.33. Разделить регистрацию, воспроизводимый профиль, результаты измерений, ограничения выбора и активную сессию. Игровые измерения реализовывать отдельным этапом после надёжного обычного подключения.

**Tech Stack:** Windows x64, Rust/Tauri, React/TypeScript, WarpScout 0.16.1, mihomo 1.19.33.

**Spec:** [Повторный анализ и предлагаемая архитектура](../../validation/upstream-reassessment-2026-10-28.md). Это подробный план следующих вех, а не заявление об их выполнении.

## Общие ограничения

- Portable означает распакованную папку без установщика и постоянно установленной службы; DLL и другие файлы допустимы. UAC при запуске разрешён. Настройки остаются в `data` рядом с EXE.
- Крестик скрывает окно в трей. Только явный выход завершает подключение и принадлежащее Tropa ядро. Ошибка очистки не скрывается успешным выходом.
- Основное подключение не требует выбора игры. Выбор сервера и раздельное туннелирование — независимые функции.
- Сохранять возможность ручного выбора. Не заменять ручной профиль автоматически при его отказе, изменении ограничений или поиске.
- Не выполнять инжект, запись памяти игры или обход античита. Не обещать отсутствие санкций и снижение ping без измерений.
- Пользователь оставил zapret включённым; официальный WARP должен оставаться отключённым. Изменять эту конфигурацию без отдельного указания нельзя.
- Не останавливать чужие процессы/службы, не очищать произвольно маршруты и адаптеры. Владение ресурсами подтверждать для конкретной тестовой сессии.
- Не возвращать импорт полной регистрации, WARP+ license key или привязку шифрования к компьютеру как обязательные функции: пользователь от них отказался.
- Приватные ключи и bearer tokens не попадают в логи, UI, ZIP, публичный каталог профилей и диагностический экспорт. Локальное хранение в отдельной portable secrets-папке сохраняется; специальное шифрование не является задачей этой вехи.
- Использовать существующие границы Config write → config update → lifecycle; изменения команд frontend проходят через существующий mutation funnel. Не добавлять второй управляющий поток ядра.
- Не обновлять upstream и зависимости массово. Новая криптографическая зависимость допустима только для отсутствующей EC-регистрации, с проверкой лицензии, форматов и зафиксированным lockfile.
- Текущие незакоммиченные изменения сохранить. Коммиты, PR и публичный выпуск выполняются отдельным действием, не механически в конце каждого пункта.

## Общая проверка изменений

Перед изменением поведения воспроизвести конкретный дефект тестом или нативным сценарием. Не создавать тесты, которые просто повторяют строки реализации. После каждого затронутого backend-контракта проверять совпадение Rust/TypeScript и поведение существующих сохранённых данных.

Настройка Rust в PowerShell:

```powershell
$env:CARGO_HOME = Join-Path (Get-Location) '.tools/cargo'
$env:RUSTUP_HOME = Join-Path (Get-Location) '.tools/rustup'
$env:PATH = "$env:CARGO_HOME\bin;$env:PATH"
$env:CARGO_BUILD_JOBS = '4'
```

Основные команды из корня проекта:

```powershell
cargo test --locked -p clash-verge --lib --features clippy,portable,tropa-probe --offline --quiet
npx.cmd --yes pnpm@12.10.0 test
npx.cmd --yes pnpm@12.10.0 run web:build
```

`web:build` включает `tsc --noEmit`. ESLint запускать по изменённым TS/TSX-файлам с `-c eslint.config.ts --max-warnings=0`. Для нового сетевого поведения обязательно отдельное нативное испытание; unit-тест не заменяет его. Исторические 396 Rust и 50 frontend тестов — исходная точка, не обещание будущего числа тестов.

## Веха 1. Различимые ошибки и диагностика

**Файлы:** изменить `src-tauri/src/core/warp_connection.rs`, `core/warp_discovery.rs`, `core/warp_probe.rs`, `cmd/tropa.rs`, `src/types/tropa.ts`, `src/pages/tropa.tsx`; создать `src-tauri/src/core/warp_failure.rs`. Общий wire-контракт `cmd/mod.rs` использовать без несвязанного рефакторинга.

**Контракт:** `FailureStage { Registration, Scanner, Validation, Runtime, Routing, Cleanup }`, `FailureReason { Unreachable, NoCandidates, Timeout, InvalidOutput, Unsupported, PermissionDenied, ProcessExited, Cancelled, CleanupPending }`; `WarpFailure { stage, reason, retryable, transport: Option<TransportKind> }`. `TransportKind` определить в `config/warp_profiles.rs`: `WireGuard`, `Awg`, `MasqueH3`, `MasqueH2`. Сериализация enum — camelCase. Чувствительные подробности не входят в тип.

- [ ] Сохранить сценарий первого сбоя selected-mode verification из `split-tunneling.md` как пример: наружу сейчас приходит слишком общее сообщение. Отдельными тестами воспроизвести несовпадение «нет кандидатов», неверный отчёт и незавершённая очистка.
- [ ] Присваивать типизированную причину в месте возникновения. Ошибка парсинга, запуска или остановки не превращается в «сервер недоступен»; отмена не считается отказом кандидата.
- [ ] Для готовности локального listener проверять readiness; повторять только временный connect/timeout до установленного общего дедлайна. Не повторять отказ аутентификации, невалидный ключ или неверную схему. До Connected разрешить максимум 3 попытки с паузами 1 и 2 секунды в пределах 30 секунд на проверку.
- [ ] Показывать короткую русскую причину и нужное действие, сохраняя `needsDisconnect`. Диагностика содержит версии/хэши, этапы, длительности, коды и счётчики; не содержит runtime YAML, токены, приватные ключи и полный дамп ответа API.
- [ ] Проверить регрессии и одну нативную неуспешную попытку: отсутствие соединения и чистая остановка должны быть честно отражены.

**Готово, когда:** пользователь понимает, нужен ли повтор, другой профиль, исправление файлов или отключение; диагностика воспроизводима и не раскрывает реквизиты.

## Веха 2. Реальная выборочная маршрутизация UDP/IPv6

**Файлы:** расширить `src-tauri/src/core/warp_smoke.rs`, `core/warp_probe.rs`, `config/tropa.rs`, `src/components/tropa/routing-picker.tsx`; добавить `src-tauri/src/bin/tropa-routing-fixture.rs`, `scripts/test-tropa-routing.ps1`, `docs/validation/split-tunneling-udp-ipv6.md`.

**Контракт:** диагностический fixture принимает `--transport tcp|udp`, `--target <socket-address>` и `--nonce <random>`, возвращает JSON `{ transport, replyMatched, elapsedMs }`. Ответ проверяется по nonce, не по одному факту получения пакета. Удалённый управляемый echo responder добавляет наблюдаемый source address; публичный IP в сохраняемом отчёте заменяется хэшем. Это отдельный тестовый бинарник, не часть обычного portable-комплекта.

- [ ] До изменения routing выполнить тест текущей реализации: два EXE с одинаковым именем в разных папках, выбран только один; проверить IPv4 TCP, долгоживущий UDP и короткие UDP sockets. Тестовый UDP target обязан быть не на порту 53, чтобы DNS hijack не подменил проверку process routing.
- [ ] Добавить burst из 100 пакетов, серию коротких sockets и 5 минут постоянного UDP. Для наблюдения внешнего источника нужен доступный управляемый responder; без него отметить соответствующую проверку как непроведённую. Не подменять его localhost или DNS-проксированием.
- [ ] Повторить для внутреннего IPv6-трафика на сети с настоящей IPv6-доступностью; отсутствие IPv6 — результат Unsupported/NotTested, а не Pass. Внешний endpoint WARP пока может оставаться IPv4.
- [ ] Проверить поведение `PROCESS_QUERY_LIMITED_INFORMATION`/UDP lookup, недоступного процесса, повторного использования порта и запуска программы после подключения. Исправлять только воспроизведённые дефекты; при системном ограничении задокументировать его и рассмотреть full-computer режим как отдельный пользовательский выбор.
- [ ] Отдельно проверить Firefox Portable/Chrome обычными HTTPS-запросами и QUIC при наличии поддерживающего клиента. Системный DNS, browser DoH и DNS через WARP оценивать отдельно; общий Windows DNS нельзя честно приписать исходному приложению.
- [ ] Снять до/после маршруты IPv4/IPv6, DNS, адаптеры, proxy; проверить очистку при отмене и аварии fixture. Не изменять штатную политику DIRECT для неизвестных процессов без нового решения.

**Готово, когда:** опубликована матрица TCP/UDP/IPv4/IPv6 с фактами и ограничениями. Успех одного HTTPS-запроса не выдаётся за игровую совместимость. Эта веха не запускает античиты и игры автоматически.

## Веха 3. Ограничения выбора и свежесть результатов

**Файлы:** создать `src-tauri/src/config/warp_selection.rs`; изменить `config/tropa.rs`, `config/warp_profiles.rs`, `core/warp_discovery.rs`, `cmd/tropa.rs`, `src/types/tropa.ts`, `services/tropa.ts`, `pages/tropa.tsx`, `components/tropa/server-picker.tsx`, `utils/tropa-server.ts` и относящиеся к ним тесты.

**Контракт:** `SelectionPolicy { allowed_transports: Vec<TransportKind>, include_nodes: Vec<String>, exclude_nodes: Vec<String>, include_node_countries: Vec<String>, exclude_node_countries: Vec<String> }`. Пустые positive-списки означают все значения; исключение имеет приоритет. Добавить `node_country: Option<String>` и явно названный `exit_country` вместо неоднозначного frontend `country`; старое поле при миграции трактовать только как страну выхода.

- [ ] Написать тесты для DME exclusion, HEL/ARN inclusion, DE/NL node-country inclusion, пересечения include/exclude, unknown metadata и ручного выбора, не проходящего ограничения. Например: `includeNodeCountries=['DE','NL']` + `excludeNodes=['ARN']` не допускает ARN и не проверяет `exitCountry` вместо страны узла.
- [ ] Нормализовать коды в uppercase, проверять длину (3 для узла, 2 для страны), ограничить список 64 значениями, удалять повторы. Противоречивую полностью пустую выборку объяснять до запуска поиска.
- [ ] Разделить фильтр отображения таблицы и ограничения соединения. Политику применять к scanner args, кэшу, выбору и повторной metadata-проверке непосредственно перед TUN. При заданных географических ограничениях неизвестная metadata требует повторной проверки; при её отсутствии профиль не активируется.
- [ ] Сохранить manual profile при конфликте, показать «не соответствует ограничениям» и отказать в следующем подключении. Не менять действующую сессию и не переходить в Automatic без действия пользователя.
- [ ] Старые измерения после смены сети/identity помечать устаревшими. Для первого выпуска всегда перепроверять кандидата перед TUN; время и сетевой контекст используются для порядка проверки, а не как разрешение пропустить её. Не сохранять SSID/MAC в диагностике.
- [ ] Страну узла получить из проверяемой metadata; текст `NODE LOCATION` разбирать только по закреплённому формату с отдельным тестом неизвестной строки. Предпочесть структурированное поле при будущем обновлении scanner adapter.

**Готово, когда:** запрещённый узел не возвращается через кэш, ручной выбор и повторное подключение, а страна выхода не обещается как неизменная страна сервера.

## Веха 4. Планировщик поиска WG/AWG

**Файлы:** выделить CLI/парсер из `core/warp_discovery.rs` в `core/warp_scout.rs`; создать `core/warp_search.rs`; изменить `core/warp_discovery.rs`, `config/warp_profiles.rs`, `cmd/tropa.rs`, frontend типы и таблицу. Сохранить существующие Windows Job Objects и execution guard.

**Контракт:** `SearchRequest { mode: SearchMode, transports: Vec<TransportKind>, policy: SelectionPolicy }`, `SearchMode { Quick, Extended }`; `TransportSearchProgress { transport, state, discovered, checked, verified, rejected, untested, elapsed_ms }`, где state — `queued|running|completed|cancelled|timedOut|failed|unsupported`. `SearchProgress` содержит общий итог и массив по транспортам; варианты I1 — вложенные метки AWG.

- [ ] Воспроизвести тестом с управляемыми часами ситуацию, когда AWG занимает весь бюджет и WG не запускается. Проверить, что медленный/упавший режим не уничтожает уже сохранённые результаты другого.
- [ ] Quick: перепроверить до трёх подходящих сохранённых кандидатов, затем выполнять ограниченные scan-задачи до первого подтверждённого подключения. Честная подпись — «быстрое подключение», а не «найден абсолютный минимум ping».
- [ ] Extended: сохранить общий предел 600 секунд, максимум 128 профилей и один scanner/validation core одновременно. Для WG/AWG сначала резервировать до 120 секунд каждому; свободное время перераспределять, но не отнимать у ещё не запущенного режима. После вехи 7 резервировать до 120 секунд каждому из четырёх режимов, остаток 120 секунд — общий резерв. Очистка учитывается отдельно и не обрывается ради красивого таймера.
- [ ] Сканировать небольшими завершёнными задачами: `-sample 1` для первичного прохода, `-sample 5` для расширения при оставшемся бюджете; затем ограниченные `-target`/sweep только по явному расширенному действию. Не считать, что убитый scanner обязательно успел записать полный отчёт.
- [ ] Проверять несколько лучших кандидатов одного режима, затем давать очередь следующему. Генератор AWG сохраняет конкретный экспортированный I1 и junk; параметры победителя нельзя заново случайно генерировать при подключении.
- [ ] Нормализовать результат без секретов: endpoint, transport, параметры профиля, узел, страна узла, страна выхода, источники/время измерений. Отдельно учитывать scanner-working, runtime-verified, rejected, untested и torn-down; схема текста проверяется snapshot fixtures закреплённой версии, не парсингом нарисованной TUI.
- [ ] Сохранить результаты после каждого успешно проверенного кандидата. Отмена прекращает новые задачи, останавливает принадлежащие процессы и сохраняет завершённые наблюдения. Продолжение поиска не меняет ручную selection.
- [ ] Ранжировать только сопоставимые наблюдения: вначале доля отказов, затем tail latency/jitter и median при наличии достаточной серии. Сохранённые 5 DNS-проб и ICMP WarpScout показывать с источником/размером выборки; не переименовывать их в ping игры. Для отсутствующих метрик не подставлять ноль.

**Готово, когда:** WG и AWG имеют независимые команды/счётчики, любой частичный результат объясним, процесс отмены не оставляет дочерних процессов, а 70 строк scanner не обязаны превращаться в 70 зелёных runtime-профилей.

## Веха 5. MASQUE-регистрация устройства

**Файлы:** создать `config/warp_masque_account.rs`, `core/warp_masque_registration.rs`; изменить `config/mod.rs`, `core/mod.rs`, `cmd/warp_account.rs`, `config/warp_profiles.rs`, `src/types/tropa.ts` и настройки. При необходимости обоснованно изменить `src-tauri/Cargo.toml`/`Cargo.lock`.

**Контракт:** отдельные `MasqueAccountStore`, `MasqueRegistrar`, `MasqueAccountStatus`. Файлы `data/secrets/masque-account.json` и `masque-pending.json`; WG файл остаётся совместимым. В UI — статусы семейств без ключей. Один MASQUE account обслуживает H3 и H2; это не четыре разных аккаунта на четыре режима.

- [x] Перенести API-последовательность закреплённого WarpScout/usque в локально тестируемую регистрацию: первоначальная запись устройства, получение ID/token, генерация ECDSA P-256 на компьютере, PATCH с публичным DER и типом MASQUE, проверка endpoint peer key и назначенных адресов.
- [x] Для crypto сначала подтвердить форматы: mihomo принимает base64 EC private key DER/SEC1 и peer public key DER/SPKI. Выбрать поддерживаемую Rust-библиотеку с нужными EC/DER-функциями, проверить лицензию и зафиксировать совместимую версию в lockfile. Не реализовывать эллиптическую криптографию самостоятельно и не превращать WG X25519 в EC ключ.

## Условные направления, не входящие в ближайшее исполнение

- **Резерв регистрации:** при воспроизводимой недоступности прямого API добавить выбранный пользователем HTTPS/SOCKS proxy или уже принадлежащий Tropa рабочий туннель. HTTP reverse relay читает проксируемые API-запросы/токены и требует отдельного решения о доверии. `base-relay` не добавлять скрытым default и не развёртывать в рамках этого плана.
- **Глубокая интеграция WarpScout:** только при измеренной проблеме CLI/парсера сделать узкий upstream-compatible JSON/JSONL adapter или fork с закреплённой схемой событий; не переписывать сейчас весь сканер на Rust. Исходники, лицензии, cancellation и сравнение с оригинальным бинарником — обязательная часть такого отдельного изменения.
- **WARP-in-WARP, полный перебор подсетей и download speed:** отдельные экспертные проверки после основных вех. Они увеличивают время/нагрузку и не являются обязательным поведением кнопки «Подключить».
