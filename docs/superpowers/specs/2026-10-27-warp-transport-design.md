# Tropa: первая живая проверка WARP

Пользователь разрешил продолжить регистрацию/ответ/подключение и испытать текущую сеть через роутер. Обход ограничений откладывается. Перед включением игрового TUN нужно подтвердить действительный транспорт, включая UDP.

Первый исполняемый срез — developer probe с отдельной Cargo feature `tropa-probe`, без Tauri startup. Он использует существующие WarpAccountStore/HttpWarpRegistrar/ensure_registration и закреплённый mihomo v1.19.33. Создание реального устройства теперь разрешено пользователем. Данные сохраняются в отдельной исключённой из Git папке .artifacts/warp-live/data/secrets; секреты не выводятся.

Probe удерживает существующую shared execution reservation, отказывается при занятом ядре, запускает дочерний процесс скрыто и применяет существующий Windows Job Object kill-on-close. Конфиг хранится внутри secrets и удаляется после остановки. TUN выключен, системный proxy и маршруты не меняются, слушатель только loopback на свободном порту, внешний controller не включается. Main app/updater не запускаются; это не native UI smoke и не обход его prerequisite.

Испытания: прямая доступность API, реальная регистрация/повторное чтение, проверка конфигурации через mihomo -t, HTTPS trace через loopback HTTP proxy с warp=on/plus и DNS по UDP через SOCKS5 UDP ASSOCIATE. Endpoint первоначально 162.159.192.1:2408, без сканирования/автоматической смены. Отказ не называется подключением; сообщается стадия, без ключей, JSON API и сырых диагностик конфигурации. JSON-отчёт содержит только технические статусы, endpoint, версии/хэши и факт остановки. Системная сеть проверяется до/после запуска.

Успех подтверждает транспорт в этой сети. Привязка к игровому .exe, координация TUN/прав/восстановления, изоляция updater перед GUI и главный переключатель — следующий срез, а не симуляция в данном тесте. Выбор .exe уже реализован и сохраняется. Не запускаем игру/античит автоматически.
