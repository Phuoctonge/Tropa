# Tropa: поиск WARP endpoint через WarpScout

Пользователь утвердил WarpScout и поручил выбрать способ интеграции. Переносим поиск перед подключением: отдельный закреплённый WarpScout 0.16.1, без форка, затем собственная проверка mihomo. Первый срез работает через developer probe, без GUI/updater/TUN; интерфейс поиска подключается после доказательства транспорта.

Версия: v0.16.1, commit 9e2ce9570625757ba24b390ad680dccd5e7f2707. Windows amd64 ZIP SHA256 48e30076631ac0106b20decd97f905184caa3fb30237caaf89c7c9c2478615e3; exe SHA256 01f11965da6415b08a23c334ea055edbda7298d46f717c2065ca94c538fb730c. MIT notice сохраняется при поставке бинарника. Бинарник пока находится в исключённой .artifacts; установщик/Go на пользовательском ПК не нужны.

Команда scan -proto wg -best -plain -no-report -sample 5 -tunnel-jobs 12 -timeout 2 -account <secret-file>. WG выбран явно; AWG/MASQUE, relay, регистрация сканером, speedtest и поиск обхода не включаются. Общий лимит 180 секунд, Ctrl+C отменяет owned child, Windows Job Object страхует аварийное завершение. Shared execution reservation исключает одновременное сканирование и работу ядра. Первоначальный прогон с 4 работниками достиг лимита 120 секунд; по исходникам полная первая фаза на недоступных портах при такой параллельности может занимать свыше пяти минут. Параметры уточнены по этому результату, без автоматической смены протокола.

Tropa использует собственную сохранённую регистрацию; временный файл содержит только private_key, peer_public_key, ipv4 и ipv6, без id/token. Файл удаляется после остановки сканера. Stdout ограничен 4 KiB, stderr не выводится. При exit 0 принимается ровно один IPv4 endpoint из известных /24 пулов WarpScout и с допустимым WARP-портом. Пустой/невалидный вывод и ненулевой exit не являются успехом.

Полученный кандидат проверяется существующим mihomo probe: HTTPS trace warp=on/plus и DNS UDP. Лишь после обоих успехов config сохраняет endpoint в warp-endpoint.json. Отказ/отмена оставляет предыдущий файл неизменным. Общий сигнал отмены сохраняется между поиском и проверкой; mihomo явно останавливается до возврата ошибки отмены. Обычный probe читает сохранённый адрес с лимитом размера и повторной валидацией; повреждённый файл не подменяется молча адресом по умолчанию. У одного запуска scan -best один кандидат; это ограниченный подбор, не полный список или гарантия оптимального игрового ping. Автосмена адреса во время игры запрещена.

Проверки: синтетический машинный вывод, адреса вне пулов, нулевой/посторонний порт, лишний stdout; экспорт без API identity; сохранение предыдущего выбора; полный Rust-набор и живая проверка на текущей сети с подтверждением cleanup. Если сканер не найдёт WG, результат фиксируется без скрытого переключения транспорта.
